# People Administration System

## Overview

This project is a small **People Administration System** designed to demonstrate a clean layered architecture for a REST API, together with a minimal web interface for performing CRUD operations.

The application allows users to create, retrieve, update, and delete people. It also demonstrates common backend development practices such as:

* RESTful API design
* Layered architecture
* Input validation
* Custom exceptions
* Centralized exception handling
* Application logging
* Unit and integration testing
* JSP-based web UI
* Bootstrap for responsive styling

---

## Main Features

### People Management

Each person contains the following information:

| Field     | Type    | Required | Description                                                                           |
| --------- |---------|---------:|---------------------------------------------------------------------------------------|
| `id`      | Integer |       No | Unique identifier generated by the system (Starts at 1000 and increase automatically) |
| `name`    | String  |      Yes | Person's name                                                                         |
| `age`     | Integer |      Yes | Person's age; must be zero or greater                                                 |
| `address` | String  |       No | Person's address                                                                      |

### Validation Rules

The following validation rules must be applied:

* `name` is mandatory.
* `name` must not be blank.
* `age` is mandatory.
* `age` must be greater than or equal to `0`.
* `address` is optional.
* `id` is generated by the application/database and should not be provided when creating a new person.

Example of a valid person:

```json
{
  "name": "John Smith",
  "age": 35,
  "address": "123 Main Street"
}
```

# Architecture

The application follows a traditional layered architecture:

```text

                +----------------------+
                |      Controller      |
                | REST API / Web       |
                +----------+-----------+
                           |
                           v
                +----------------------+
                |       Service        |
                | Business Logic       |
                +----------+-----------+
                           |
                           v
                +----------------------+
                |     Repository       |
                | Data Access Layer    |
                +----------+-----------+
                           |
                           v
                +----------------------+
                |        Model         |
                | Person / Data Model  |
                +----------------------+
```

The objective of this structure is to keep responsibilities separated and make the application easier to maintain, test, and extend.

# Controller Layer

The controller exposes the REST API.

A typical REST endpoint structure is:

| HTTP Method | Endpoint              | Description         |
| ----------- |-----------------------| ------------------- |
| `GET`       | `/api/v1/people`      | Retrieve all people |
| `GET`       | `/api/v1/people/{id}` | Retrieve one person |
| `POST`      | `/api/v1/people`      | Create a person     |
| `PUT`       | `/api/v1/people/{id}` | Update a person     |
| `DELETE`    | `/api/v1/people/{id}` | Delete a person     |

### Get all people

```http
GET /api/v1/people
```

Response:

```json
[
  {
    "id": 1000,
    "name": "John Smith",
    "age": 35,
    "address": "123 Main Street"
  },
  {
    "id": 1001,
    "name": "Jane Smith",
    "age": 28
  }
]
```

### Get a person

```http
GET /api/v1/people/1000
```

### Create a person

```http
POST /api/v1/people
Content-Type: application/json
```

```json
{
  "name": "Robert Brown",
  "age": 42,
  "address": "456 Oak Avenue"
}
```

### Update a person

```http
PUT /api/v1/people/1000
Content-Type: application/json
```

```json
{
  "name": "John Brown",
  "age": 36,
  "address": "789 Pine Street"
}
```

### Delete a person

```http
DELETE /api/v1/people/1000
```

# Custom Exceptions

Custom exceptions make application errors explicit and easier to handle.

Example:

```java
public class PersonNotFoundException extends RuntimeException {

    public PersonNotFoundException(Long id) {
        super("Person with id " + id + " was not found");
    }
}
```

A centralized exception handler convert exceptions into consistent REST responses.

For example:

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(PersonNotFoundException.class)
    public ResponseEntity<Map<String, Object>> 
        handleResourceNotFound(PersonNotFoundException ex) {

        // ...
    
    }
}
```

This prevents controllers from having to implement repetitive error-handling code.

# Logging

The application uses a logging framework rather than `System.out.println()`.

Logging are available at appropriate levels:

* `DEBUG` — detailed information useful during development.
* `INFO` — important application events.
* `WARN` — unexpected but recoverable situations.
* `ERROR` — failures requiring attention.

Example:

```java
private static final Logger logger = 
        LoggerFactory.getLogger(PersonRepository.class);

public Collection<Person> getAll() {
    logger.info("Processing getAll at repository layer");
    return personMap.values();
}
```

Logs provide useful diagnostic information without exposing sensitive information.

# Separation Between REST API and JSP UI

The REST API and JSP UI remain conceptually separated.

The REST API provides machine-readable operations:

```text
/api/v1/people
```

while the JSP layer provides human-facing pages:


Both uses the same service layer.

```text
                    +----------------+
                    | Person Service |
                    +-------+--------+
                            |
                 +----------+----------+
                 |                     |
                 v                     v
        +----------------+    +----------------+
        | REST Controller|    | Web Controller |
        +----------------+    +-------+--------+
                                      |
                                      v
                                  JSP Views
```

This prevents business logic from being duplicated between the REST API and the web interface.

# Summary

The People Administration System is a small but complete example of a layered Java web application.

It demonstrates:

* RESTful API development
* CRUD operations
* Person validation
* Layered architecture
* Controller / Service / Repository / Model separation
* Custom exceptions
* Centralized error handling
* Application logging
* Unit and integration testing
* JSP server-side rendering
* Bootstrap-based UI
* Reuse of business logic between REST and web interfaces

The project is intentionally small so that the architecture and development practices can be easily understood while still representing patterns commonly used in larger enterprise applications.
